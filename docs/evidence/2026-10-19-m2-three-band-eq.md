# Motif Forge M2 三段 EQ 验收

2026-10-19；覆盖 MF-P05/P06/P11/P13/P15/P16/P17/P18/P21。M2 通过验收；一次 fresh 独立审查与唯一窄修复复核完成，没有剩余阻塞。Git checkpoint 由同轮开发分支提交与正常推送回执记录，main 不变。

已保存的双钢琴基础混音现在可以调整低、中、高频，使用总旁路、三段归零和恢复保存的 EQ。调整先进入草稿；保存后显式生成该版本的试听或导出。重开恢复参数，Undo 恢复精确版本；原谱音符、片段、来源和原 Track 保持不变。

这里只增加选中轨的 EQ 小面板。两套候选配色仍未选定；没有整页改版、实时调音、频率/Q 编辑、EQ 自动化或频谱分析。界面曲线表达新增 EQ 的参数响应，不是正在播放音频的频谱，也不代表包含 limiter 的完整输出链。

## 已测到的结果

| 检查 | 结果与边界 |
|---|---|
| 真实滤波 | 180 Hz 低架、1 kHz 峰值/Q 0.8、6 kHz 高架；各段 −12 至 +12 dB。原 M1 音频链保留，其后最多增加三个原生 biquad |
| 低资源选择 | 只为可听轨创建非零段；总旁路或全零不增加滤波节点。无新增依赖、音源、FFT、常驻 AudioContext 或刷新循环 |
| 曲线正确性 | 生产共享模块对照 native 频响与实际 PCM；15 组设置、75 个采样频点，PCM/曲线最大误差约 0.0000011 dB，仅适用于本次有界探针 |
| 旁路/归零 | 正式 Worker 钢琴输出与 M1 基线相差不超过 1 个 PCM24 LSB；激活 EQ 确实改变实际音频 |
| 保存与恢复 | built UI 三次保存，每次一个命令；旋钮一手势一个草稿 Undo，拖动不发服务端 Job；数值非法/Escape、重开、旁路保留参数、归零与精确持久 Undo 均通过 |
| 同版试听导出 | Preview、Canonical 和 Export 使用同一 Revision/graph/hash；Master 与两个 Stem 的和相差不超过 2 LSB；导出工程保留 EQ/mix，MIDI 保留原音符，不携带 EQ 音效 |
| 静音 | 全静音 WAV 为精确零 PCM，静音 MP3 可正常生成与解码；仅可信 Revision/Snapshot 的 expectedSilence 能放行 |
| 请求边界 | 越界、字符串数值、字符串布尔、未知 profile 四类 HTTP 请求返回 422，分支 head 不变；旧版本 MP3 不继承给新 EQ 版本 |

真实媒体为内部两小节、4 秒、两轨固定样本，共 13 份音频；不是整首经典作品或主观音质验收。另有真实 PostgreSQL 测试从审核乐谱导入/伴奏保留开始，验证 JSONB、幂等多命令、精确退出 EQ 的 v4 hash，以及即使 Undo 后仍阻止不安全历史降级。既有旧 v1–v4 不按新 EQ 解释。

MP3 是有损格式。相对同源 WAV 的 RMS 差为试听 −0.4461401 dB、导出 −0.0002135 dB，在预先声明的 0.5 dB 容差内；未做响度归一化，不据此宣称 LUFS/true-peak 或审美达标。提升频段可能提高输出电平，既有 limiter 行为保留。

- Python unit/Eval/root 共 **838 项**、Web **115 项/42 文件**（单 worker）、Audio/Render Worker **124 项/16 文件**通过。
- Mypy **133 个源文件**、Ruff、diff、Web/Audio build 和 TypeScript 检查通过；新增真实 PostgreSQL 集成 **1 项**通过。
- 最终 built UI/生产 Worker/Parent export 路径 **15 个 Job**，Parent export 在 fresh app 中重复 resume；连同前两次探针尝试实际共 **25 个 Job、0 个 AI Run**。不是 Redis/Celery 传输或 Compose 重启验证。
- Web 构建 JS gzip 124.72 kB、CSS gzip 14.30 kB；M1 对应为 120.83/13.81 kB。是构建文件量，不是进程内存。
- 单宿主 4 秒信号、每模式 5 次的生产模块暖中位耗时：M1 链 33.25 ms、三段全开 36.60 ms、旁路 32.10 ms。只反映这个小探针，不是生产 CPU/RSS/P95 或整曲端到端延迟。

## 失败记录与修复

1. 真实 PG 首次迁移暴露 SQLAlchemy 把紧凑 JSON 中的 `:48000` 等视为绑定参数，生成非法 JSON。已修正迁移和 metadata 的 JSON 分隔空格，保留失败记录，真实新 PG 复验通过。
2. 旋钮草稿预览曾吞掉松手提交、长按方向键曾产生多个 Undo。对应交互测试先 RED，再以一手势一次提交修复，聚焦 14 项通过。
3. 组合测试首次有 1 个旧迁移 head 断言仍指向 0028。同步为实际 0029，继续要求唯一可逆 head；没有放宽音频或数据断言。最终 838 项通过。
4. 前两次浏览器探针分别因手动鼠标坐标位于屏幕外、以及 reset 后立刻读值早于 React 更新而失败。改为正常滚动和等待原本可观察的 0/6 参数，不修改产品行为、不放宽值；原失败截图、说明和各次 Job 数保留。

初始缺模块的测试收集失败不计作行为 RED；旧 Web 并行等待超时仍按 M1 记录保留，本次串行通过不代表该问题已修复。
