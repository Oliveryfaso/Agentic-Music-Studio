## 发现

### M2-R1 / Minor / 已关闭：释放修饰键会把一次持续方向键手势拆成两个 Undo

位置：[PianoEqPanel.tsx:83](../../apps/web/src/features/studio/PianoEqPanel.tsx#L83)，结束逻辑第 69 行。

- **实际行为与复现：** 从中频 0dB 开始，按住 Shift+ArrowUp，重复一次；保持 ArrowUp 按住、先释放 Shift。所有 `keyup` 都调用 `finishKey()`，此时就提交 0.2dB。随后 ArrowUp repeat、最终松开 ArrowUp，又提交 0.7dB，historyCursor 为 2。独立 jsdom 第 2 个 case 明确断言这两个实际提交。
- **影响：** 最终 EQ 数值正确，保存仍只在用户点击时发生，没有重复 Job/费用或源谱损坏；但一次持续按键要两次草稿 Undo 才完全撤回，违反“一次长按一个 command”。普通不带修饰键长按的独立对照为 1 command。
- **最小修复：** 只让实际调参键的释放结束键盘手势，忽略 Shift 等修饰键的 keyup；失焦仍可结束。无需改领域 Undo。
- **触发与最晚处理：** 用户长按时切换细调 Shift 即触发；下次键盘交互修整或发布前处理。按当前实际影响列 Minor，不把它描述为声音或持久化故障。

### M2-R2 / Minor / 已关闭：保存版仍是 v3 时，未保存混音草稿会提前开放 EQ

位置：[PianoEqPanel.tsx:20](../../apps/web/src/features/studio/PianoEqPanel.tsx#L20)，门控第 26 行；调用方 [MixerPanel.tsx:30](../../apps/web/src/features/studio/MixerPanel.tsx#L30)。

- **实际行为与复现：** 打开 saved v3 双钢琴，EQ 最初不可用；点击原轨静音，让草稿进入 v4，但不保存。EQ 立即出现并可编辑，`savedArrangement` 仍是 v3。独立 jsdom 第 3 个 case 复现。门控只检查 draft 的 `readPianoEq()`，没有检查 saved 版本。
- **影响：** 跳过 spec 明确要求的“v3 需先通过 M1 保存进入 v4”，并且没有可恢复的已保存 EQ 值。领域已明确支持 mix→EQ 同批应用及逆序精确 Undo，所以这里未见数据损坏、旧版本静默改写或非法声音冒充；属于 UI 范围与引导不一致。
- **最小修复：** EQ 面板同时要求 `savedArrangement.schema_version` 为 v4/v5；v3 的混音草稿仍显示先保存提示。保留领域的混合批次兼容与 Undo 测试。
- **触发与最晚处理：** 从 v3 首次启用混音但尚未保存时触发；发布前或下次 M1→M2 入口整理时处理。
