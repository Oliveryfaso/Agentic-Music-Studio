### Important 1：只改密度/力度的局部任务实际改变了既有和声

- 位置：`services/api/src/motif_forge/providers/piano.py:89` 承诺保留既有和声，`services/api/src/motif_forge/application/piano_semantic.py:85`–95 的保存前验证仅检查 Plan/schema/编译范围，不验证该承诺；对应 `domain/piano_plan.py` 接受新 Plan 中全部合法 chord。
- 触发：真实 UI 验收描述为“只把第9到12小节的新增伴奏改得更稀疏、更轻；每小节只在第一拍奏一个根音，力度比现在低，其余小节和原旋律保持不变”。用户没有请求换和声；Provider system prompt 明确 `Preserve existing harmony unless the intent asks otherwise.`。
- 已发生的结果：`research/output/playwright/p22-semantic-live/browser.json` 内 first plan 的9–12小节和弦为 **C/D/Em/G**，second plan 为 **Em/D/C/G**。9、11小节被调换；同一第二计划的摘要又称保留和声进行。工程验收只测音符数/力度/范围外相等，未发现这一语义退化。
- 影响：试听/HITL仍存在，原谱和范围外内容仍精确保留，但“改疏、改轻”这条核心新路径会额外改变用户未请求的音乐内容。不能把本次 live 判为已证明该保留和声承诺。
- 最小修复方向：为当前 modify 确立可验证的和声约束，从已保存 Plan 或可无歧义验证的当前音符取得逐bar和声，将明确和弦上下文送入模型，并在候选保存前确定性核对/固定；不可确定时明确拒绝或缩小支持范围。暂不增加泛化的意图分类/新 Agent。不要只再加一句 prompt，也不要用付费重试掩盖。补一条该真实反例的离线验证，保留原始 live 证据与修复前限制。

### Important 2：提交后无回执的失败被投影为已知0 tokens

- 位置：新增 `services/api/src/motif_forge/api/piano.py:154`–158 原样投影 AIRun 的 totals/status；关联现有 `providers/deepseek.py:474`–514 在 timeout/network/HTTP/protocol error 时离开，只有515–516在解析有效回执后记 usage；`infrastructure/persistence/ai_runs.py:1403`–1406 预留只增加请求计数。AIRun 初始 `total_tokens=0, model_usage_status=known`。
- 触发：请求已做持久预留并进入 HTTP，随后 read timeout，或进程在发送后、回执持久化前中断。
- 离线复现：`research/p22-independent-probe.py` 用实际 DeepSeekJsonClient + `httpx.MockTransport` 制造 ReadTimeout，再用实际 piano router 投影对应的失败 Run。运行无外网、假 key、无PG；输出：

    "phase":"failed","error_code":"DEEPSEEK_TIMEOUT",
    "model_requests":1,"total_tokens":0,"usage_status":"known"

- 影响：一请求硬上限仍防止自动第二次付费，但当前失败用量不真实，无法正确区分“没花费”和“已提交、费用未知”。这不是说本轮已发生超预算：本轮2次真实成功调用均有回执；是新增失败/恢复路径的确定性缺陷。
- 最小修复方向：对本轮未 observed 的已提交 reservation 做明确 unknown 结算或在权威读取/投影中保留未知状态；不能把未知累计成0。兼顾成功后能恢复真实 totals，且旧 known usage 不丢失。补 timeout 和“已reserved未result重启”代表性离线/现有PG测试，确认仍无第二HTTP。范围仅限必要的预算事实修复，不要求扩大故障矩阵。
