## 修复范围

默认启动路径原先在初始化运行环境后才隐式安装缺失的 Web 依赖，
`--check` 也未检查 Vite。现在支持版本检查后立即检查已安装的 Vite；
缺失以 exit69 提示 `npm ci`，在读取私有配置、创建 runtime / 存储或执行
Docker 前停止。帮助仍不依赖运行环境；不自动安装软件。

真实 shell 入口六种缺依赖路径先 RED、后 GREEN；连同原版本 / 帮助场景
与新增 CI 合同检查共22项通过。外部命令使用拒绝执行的 stub，启动器入口
保持真实，没有用模拟函数替换待测逻辑。

开发指南的日常检查改为既有 API / renderer 的只读 health GET。
旧 `check_compose_runtime.sh` 包含 schema0016、临时容器和调度器停启，
明确标为历史集成脚本，本批没有执行或改写它。

## CI 合同

新增两个标准 Ubuntu 任务，各15分钟，固定官方 Action 完整提交身份，
仅 `contents: read`，不保留 checkout token。依赖由 npm / uv 锁文件安装。
Python 运行 pytest、核心 Ruff F 检查与脚本语法 / 编译检查；Web / audio
运行单测、类型检查与构建，再只解析默认 Compose 配置，核实 Key 为空、
外部 trace 关闭。没有 Compose 启动、服务容器、迁移或付费模型调用。

CI 明确清空真实集成 opt-in，未提供数据库或渲染镜像的用例会跳过。
公开回归通过不证明完整首装、真实 Key 生成、音质、浏览器下载或应用恢复。
Ubuntu 的实际状态以对应提交的 Actions 回执为准，不用本机结果代替。
